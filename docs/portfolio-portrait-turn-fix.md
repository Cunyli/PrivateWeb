# Portrait 翻页双重换图修复 · 2026-10-28

## 实际问题

前次帧率和最终页码检查没有覆盖回弹阶段的照片内容，不能作为此问题已修复的证据。本轮连续截图捕获到了旧组重新露出的现象。

弹簧积分允许进度超过 1，原网格把这个进度直接用于纸页角度，且终点仍可能保留弯曲。翻动页因而会穿到静止的旧页面下面，深度测试让旧照片重新盖上来；最后绘制新组的静止页面时，又出现一次换图。与此同时，底层 HTML 页面在 prepare 阶段提前换成了另一组的半页，造成额外的交接路径。

## 修复

- 静止的两页先绘制，再清空深度缓冲绘制翻动页。翻动网格仍保留自身的深度测试，避免取消自身遮挡或重新出现三角形接缝。
- 可见几何进度限制在 0–1，两端的残留弯曲归零；弹簧内部的回弹计算保留。
- 画布准备好后，底层 HTML 页面只保留测量、键盘与点击目标，不再叠加绘制照片。
- 翻页期间保持原组 HTML 状态，完成时先绘制准确终点，再提交页码和链接状态；回退路径显式恢复 HTML 显示。
- 保留原照片、原比例、页面尺寸和柔软弯曲的形式。

## 验证

- `node scripts/check-portrait-book-transition.cjs`：当前代码通过。检查双向端点越界、残留弯曲、准备期间不换底层照片、精确结束姿态，以及异步准备取消后不提交旧结果。
- 将检查指向修复前网格时，出现 `spring overshoot or residual bend moved the sheet through its resting layer`；指向旧 hook 时，出现 `forward preparation exposed the incoming HTML page`。
- 内置浏览器 1440×900，开发慢速逐帧检查正反方向，捕获到了原始弹簧进度 1.0177 和 1.0159 的回弹区间。可见照片保持新组，完成提交时没有旧组重新出现。
- 对应回弹区截图与最终静止画面，在相同滚动位置的书页区域进行逐像素对照：正向平均通道绝对差 0.049/255，反向 0.063252/255。该比较针对固定视口的照片身份及终点连续性，不是性能指标。
- Safari 普通速度分别检查下一组、上一组，页码依次 1→2→1，并保存结果截图。
- 普通速度下检查左右拖动和键盘方向键，页码与最终照片一致，拖动没有误跳转；最终浏览器错误日志为空。照片点击进入约拍，以及约拍返回 Portfolio 的往返导航已检查。类型检查通过。
