# 评分驱动的照片展示

## 唯一规则

| 照片状态 | 普通 Portfolio 相册 | 约拍页 / 人像书 | 封面与分类轮播 | 精选组 |
| --- | --- | --- | --- | --- |
| 不评分 | 保留 | 不展示 | 不使用 | 不收录 |
| 0 | 不展示 | 不展示 | 不使用 | 不收录 |
| 1 | 保留 | 人像素材可展示 | 从合适的 1 中选择 | 收录 |

原有发布状态仍有效；普通私人相册不会因为评分而整体公开。人像素材池中已发布的单张照片，评分 1 即表示选入人像展示。取消 1 后约拍页与精选组同步退出；0 通过可恢复回收站处理。新照片默认不评分，不继承被替换照片的评分。

## 一个素材池，按标签取用

所有 Portrait Booking Samples / portrait-library 照片在 `/admin/curation` 合为「人像素材库」。保留原数据库照片、来源相册和标签；人物、地点、风格可组合筛选，搜索也包含标签。修改逻辑分组不会重建照片或丢失评分。

公开约拍系列由 `model:` / `series:` / `location:` 标签组织；缺少人物标签的素材合在普通 Portraits 组，不猜测人物身份或把多个地点误写成一个地点。摄影师介绍只使用 `model:Lijie` 的 1。少量旧版已公开素材缺少标签，通过有记录的精确 ID/source 修复，而不是继续依赖文件名兜底。

## Portfolio 与封面

普通系列仍可浏览未评分和 1；0 被发布状态和展示门禁双重过滤。轮播、瀑布、地图缩略图、分类预览、相册默认进入的照片统一取自 1。系列没有 1 时保留文字入口，不借用未评分照片做封面。

`/work/selected` 是独立的精选组，入口位于原有作品轮播中。它是查询视图，不复制照片、不修改原相册。UI 用 0 作为该入口的虚拟 key，数据库不创建 ID 0。普通分类浏览保留未评分照片；分类预览仅请求 `featured=1`，点击时带上确切照片 ID，避免进入时跳到另一张图。

## 约拍与翻页

首屏、人物介绍、流程配图、系列和大图浏览均只接受 1；移除旧静态照片补位。人像书按标签在不同拍摄系列间交错选取 12 张 1，保持已有柔软翻页和每页多图。单张照片的系列保留原比例并限制尺寸，避免筛选后突然铺满整个屏幕。

远程图片直接画入 canvas 会触发 Safari 的跨域纹理限制。人像书使用 `/api/photo-texture?pictureId=…&width=640` 的同源预览：仅接收已入选的正数 ID、640/1280 两档宽度；只向配置的图片域名取位图，限制类型和体积，不接受用户 URL、不转发凭证。每次先检查当前入选状态，再复用不可变源图缓存；HTTP 响应要求重新验证。纹理遇到 SecurityError 时释放资源并回退，避免翻页永久锁住。

## 新增、编辑与缓存

后台编辑现在按已有 ID / 确切存储路径族保留原记录；不再删除重建整个相册。相同 DSC 文件名不视为同一照片。改标签、排序保留 0/1 和发布状态；替换成另一张照片生成新 ID，原照片进入回收站。未评分新照片不会自动成为封面。

普通编辑不再暗中清理 R2 原图。后台已有的明确删除整个相册操作是独立流程。保存、编辑、新增和删除均失效展示缓存；选片保存后刷新服务端布局数据，避免沿用旧封面。

## 数据迁移与验证

先运行 `photo-curation-catalog-20261028.sql`，新增服务端专用、security invoker 的只读素材目录；匿名和普通 authenticated 均无 RPC 执行权限。`photo-curation-tag-repair-20261028.sql` 只补齐五张旧版已展示、已评 1 的素材标签，使用精确 ID/source 条件及不区分大小写的标签匹配，不改变任何评分或发布标志。

当前数据核对：500 张、38 个逻辑分组；人像池 74 张；307 张 1、67 张 0、126 张未评分，与改动前逐 ID 核对一致。约拍素材 36 张，35 个公开系列有 1 可用作封面。数量随日后选片自然变化。

本地检查：

```bash
node scripts/check-photo-curation.cjs
node scripts/check-photo-library-sync.cjs
node scripts/check-portrait-book-transition.cjs
node scripts/check-supabase-security.cjs
pnpm exec tsc --noEmit --incremental false
pnpm build
```

评分/封面检查涵盖无静态补位、普通相册保留未评分、统一人像池、不同系列交错取图、同源纹理门禁与拒绝任意 URL。实际后台 PUT 回归验证 ID/1/0 保留、遗漏照片进入回收站、新照片不评分、不清空存储、仅新图启动 embedding。数据库只读断言验证目录完整、仅含 1、不含 0/未公开草稿，且 RPC 服务端专用。

独立 WebKit 公共页面检查：约拍 DOM / 接口均为 1；267 个分类预览记录全部为 1；普通分类仍有未评分照片；95 个封面节点均对应 1，没有 1 的系列使用文字入口。精选浏览器为 307 张，普通巴黎相册为 16 张。12 张人像书照片使用同源缩略图，四次前后翻页依次到 2 / 1 / 2 / 1，无页面脚本异常；390×844 和 844×390 无横向溢出。稳态 6 秒窗口约 60 FPS、p95 18ms；有少量长帧，最高 67ms，属于本机测试结果，不是所有设备或每帧均达标的承诺。

管理员 UI 使用隔离的认证与 API fixture，确认 74 张人像在单一素材池、人物+地点组合筛选、Xiya 的 8 张 1、放大预览和 320/390 宽布局；浏览不会发起写请求或产生待保存项。额外将同一批已批准图片临时换成跨域来源，实测触发纹理 SecurityError 后仍可从第 1 组翻到第 2 组、释放按钮且无未处理异常；这项故障测试未改变真实素材。
